02

문제 정의

현장 배경

  • 후문 일대는 학생 유동인구가 집중되는 동시에, 좁은 골목에 보행자·차량·오토바이·PM(전동킥보드)이 혼재되어 상시적 사고 위험이 존재합니다.
  • 제안서는 후문 삼거리의 교통 환경 변화를 고려해, 보행자와 이동수단이 섞이는 구간의 안전 관리 대응 체계를 검토했습니다.
  • 후문 주택가·원룸촌은 야간 조도 저하와 인적 드문 환경으로 학생들의 귀가 불안감이 높은 구역입니다. (인하대학신문 및 지역 언론 보도 기반)

기존 운영의 세 가지 한계

한계현재 구조결과
정적 순찰고정 경로를 반복하는 방식실시간으로 변하는 위험에 즉각 대응 불가
사후 대응사고 발생 후 처리에 집중예방적 개입의 부재
근거 부재인력·예산 배분의 객관적 기준 없음자원 배분이 경험과 관행에 의존
안전 인력이 10명뿐일 때 누구를 어디로 보낼 것인가. 정비 예산이 1,000만 원일 때 어느 골목의 가로등부터 고칠 것인가.

위험을 지도에 표시한 다음, 운영자가 선택할 행동 대안과 우선순위까지 연결하는 것을 목표로 삼았습니다. 즉시 대응이 필요한 순찰과 시간을 두고 집행하는 시설 정비를 같은 위험 데이터에서 판단하도록 문제를 정의했습니다.

02A

기획 과정

팀장 조율

4개 전공 5인이 서로 다른 언어로 문제를 보고 있었기 때문에, 먼저 “무엇을 감지하는가”보다 어떤 자원을 어떤 시간축으로 배분할 것인가를 공통 문제로 잡았습니다. 역할은 위험 정량화·디지털 트윈·정책/법규·물류·엣지 인프라로 나누되, 모든 산출물이 상태–행동–결과라는 하나의 의사결정 흐름에 연결되도록 조율했습니다.

우선순위먼저 정한 질문후순위로 미룬 것
P0 · 단기 안전지금 어느 구역에 순찰 인력을 보낼 것인가?전체 캠퍼스 확장, 완성형 하드웨어 도입
P1 · 장기 정비누적 위험 로그를 기준으로 무엇을 먼저 고칠 것인가?예산 집행 자동화, 외부 기관 연동
검증실제 후문 생활권 데이터를 넣고 고정 순찰과 비교할 수 있는가?현장 실험 대신 SUMO 디지털 트윈으로 반사실적 비교
협업 에피소드

전공별 제안이 충돌할 때 회의에서 결론을 밀어붙이기보다, 순찰 경로·정비 우선순위를 한 화면에 놓은 두 가지 대시보드 안을 직접 만들어 비교했습니다. 이 과정에서 팀원들의 전문성이 더 잘 드러나는 안을 채택하고, 팀장으로서 제 초기 안을 수정했습니다.

02B

AI 에이전트 활용 설계 과정

본인 지휘

Claude Code와 Codex로 설계안과 검증 항목을 반복 정리했습니다. 에이전트가 제안한 상태·행동·보상 후보를 바로 채택하지 않고, 후문 생활권의 도로·시설 맥락과 팀의 안전 기준에 맞는지 제가 판정했습니다. 이 과정은 개념 설계를 위한 작업이며, PPO 학습이나 SUMO 실행 성과를 뜻하지 않습니다.

순서프롬프트와 에이전트 작업본인이 직접 결정한 지점
1. 구조화“위험 신호를 상태·행동·보상 후보로 나누고, 각 항목의 입력 출처와 누락값을 표로 정리하라.”순찰 재배치와 정비 예산을 같은 최적화 문제로 묶되, 시간축은 단기·장기로 분리
2. 반복 생성시나리오 매트릭스, 상태/행동 타입, 대시보드 표·문구, SUMO 대조군/실험군 체크리스트 생성PPO의 상태·행동·보상 정의와 ΔSafety - Cost - Response_Time 가중치 설계 기준 결정 · 실제 값은 검증 후 보정
3. 일관성 검증아키텍처의 입력이 PPO 상태에 빠짐없이 연결되는지, 대시보드 지표가 결과 지표와 일치하는지 diff로 점검실제 측정 전 수치를 성과처럼 쓰지 않기, 예시 UI 값과 시뮬레이션 결과를 명확히 분리

이 프로젝트에서 AI 에이전트의 역할은 “설계자를 대체”하는 것이 아니라, 팀장이 정한 문제 구조를 빠르게 여러 안으로 전개하고 누락을 찾는 것이었습니다. 최종 설계와 팀 간 우선순위 조정은 제가 맡았습니다.

본인 설계

인식 — 무엇이 위험한가

기술역할
YOLOv11 (또는 YOLOv8)보행자·차량·오토바이·PM 실시간 객체 검출
ByteTrack객체별 이동 경로 추적 (Multi-Object Tracking)
수집 지표보행 밀집도, PM·오토바이 주행 속도, 불법 주정차 체류 시간

정량화 — 얼마나 위험한가

단순 빈도 통계가 아니라 교통공학의 표준 대리 지표(surrogate safety measure)를 채택했습니다.

지표정의해석
TTC
Time-to-Collision		현재 속도와 경로를 유지할 때 충돌까지 남은 시간값이 작을수록 위험
PET
Post-Encroachment Time		두 객체가 동일 지점을 통과한 시간 차값이 작을수록 아슬아슬한 상황

상황 가중치 제안값 · 실측 보정 전

조건가중치
개강 시즌 및 축제 기간× 1.4
우천·강설 (시야 차단)× 1.3
목요일 저녁 시간대× 1.2

예측 — 한 시간 뒤는 어떤가

LSTM 또는 XGBoost로 수업 종료 시간, 날씨, 요일 특성을 반영한 1시간 후 위험도를 미리 예측합니다. 사후 대응이 아닌 선제 배치를 가능하게 하는 장치입니다.

의사결정 — 무엇을 할 것인가

조치가 이후 위험 상태와 가용 자원에 영향을 주는 순차적 의사결정으로 보고, PPO(Proximal Policy Optimization) 기반 에이전트를 개념 설계했습니다. 규칙 기반 배분보다 효과적인지는 같은 시나리오에서 비교해야 합니다.

구성내용
State
상태		시간대별 유동인구 밀도 / PM·오토바이 주행 속도 / 조도 센서 측정값 / 최근 1시간 내 위험 제보 발생 여부
Action
행동		① 인근 순찰 대원에게 해당 구간 이동 명령 하달
② 위험 구간 지능형 조명 밝기 상향 제어
③ PM 업체 서버 연동을 통한 강제 감속 지오펜싱 적용
④ 정비 대상 등록 — 장기 트랙으로 이관
Reward
보상		TTC·PET 수치 개선량, 위험 신고 접수부터 현장 조치까지 걸린 시간의 단축 정도

보상 함수

Reward = w₁ · (ΔSafety) − w₂ · (Cost) − w₃ · (Response_Time)
  • ΔSafety — 조치 후 위험 감소량 (최대화)
  • Cost — 투입 자원 비용 (최소화)
  • Response_Time — 대응 소요 시간 (최소화)

선택 기준 — 안전 향상·비용·대응 시간의 균형을 보상 함수에 반영하는 설계입니다. 서로 다른 단위의 정규화와 가중치 결정은 남아 있으며, 가중 합만으로 Pareto 최적해를 검증한 것은 아닙니다.

관제 대시보드 설계

설계 원칙

원칙의미
Situation Awareness
상황 인지		접속 즉시 후문 전반의 안전 상태를 직관적으로 파악할 수 있도록 핵심 지도를 중앙에 배치
Data-Driven Action
데이터 기반 행동		단순 정보 출력이 아니라, AI가 분석한 위험도에 따라 운영자가 즉시 우선순위를 결정하고 명령을 내릴 수 있는 구조
Integration
통합성		단기 대응(순찰)과 장기 개선(정비) 데이터를 한 화면에 통합해 상호 보완적 운영을 유도
A실시간 현황 관제중앙 · 지도 기반

“지금 후문은 안전한가? 순찰대 경로를 어떻게 짜야 하는가?”

지능형 위험 히트맵

  • 후문 일대 디지털 트윈 지도 위에 YOLOv11로 수집된 실시간 지표를 가중 합산해 색상으로 오버레이
  • Red(고위험) — TTC·PET가 설정한 안전 기준보다 낮아진 지역
  • 교통 환경 변화가 있는 후문 삼거리 교차로 인근을 점선 테두리로 강조하는 화면 구성

순찰 자원 실시간 트래킹

  • 파란 아이콘 — 현재 근무 중인 순찰 대원의 GPS 위치
  • 파란 실선 — 해당 대원의 최근 이동 경로
  • 점선 경로 — PPO 알고리즘이 현재 위험 분포를 반영해 실시간 계산한 최적 경로. 대원이 이 경로를 따라 이동하도록 전용 앱으로 전송됩니다.
B정비 요청 패널우측 · 리스트

“학생들의 불편 사항은 무엇이고, 어떤 시설 개선이 가장 시급한가?”

AI 분류 기반 정비 제보 리스트

  • 학생 전용 앱으로 접수된 사진 제보가 실시간 로딩
  • 컴퓨터 비전 모델이 사진을 분석해 썸네일 | 위험 유형(조명 고장·포트홀·PM 방치) | AI 판정 위험도(상/중/하) | 제보 위치로 자동 분류

즉시 정비 필요 고위험 시설물 Top 5

  • 제보 리스트와 누적 위험 로그(Hazard Log)를 함께 분석해 장기적 개선이 필요한 시설물의 우선순위 산출
  • 단순 제보 건수가 아니라 해당 지역의 사고 발생 가능성을 종합해 순위를 결정
    예: #1 A골목 가로등 파손 — 주변 조도 저하 및 PM 통행량 많음으로 1순위
C운영 통계하단 · 분석

“도입 후 캠퍼스는 실제로 안전해졌는가? 운영 효율은 얼마나 향상되었는가?”

  • 주간 평균 위험 지수 추이 — 꺾은선 그래프. X축 주차, Y축 평균 위험 지수
  • 자원 배분 최적화 전후 대응 시간 비교 — 막대그래프로 기존 정적 순찰과 AI 최적화 순찰을 대조. 보상 함수의 ΔSafety와 Response_Time을 검증 후 비교할 지표로 배치

검증 계획 — 디지털 트윈

항목내용
환경SUMO(Simulation of Urban MObility)에 후문 도로와 보행 흐름을 반영한 비교 환경을 구축할 계획. 실제 관측값과의 보정 필요
대조군기존 고정 노선 순찰 방식
실험군제안하는 AI 기반 동적 순찰 방식
측정 지표① 사고 발생 예측 지점 도달 시간
② 구간별 보행자 위험 노출 시간 총합
③ 단위 시간당 순찰 인력의 안전 커버리지 면적
검증 설계의 이유와 한계

현장에서 위험한 상황을 의도적으로 만들지 않고, 같은 유동인구·교통 조건에서 순찰 정책만 바꿔 비교하려는 계획입니다. SUMO 실행 결과나 위험 감소율은 아직 제시하지 않았습니다. 시뮬레이션을 수행하더라도 실제 사고 감소 효과와는 구분해야 합니다.

09

설계 결과와 검증 범위

완료한 산출물은 순찰·정비 이중 트랙, 상태·행동·보상 정의, 수집–분석–실행 아키텍처, 관제 화면 구성, SUMO 비교 계획입니다. 실제 배치나 학습 성능을 입증한 단계는 아닙니다.

산출물후속 검증 대상현재 상태
인하대 후문 디지털 트윈실제 지역의 도로·시설 맥락을 반영할 대조군·실험군 비교개념 설계 완료 · 환경 구축·실험 실행 전
PPO 자원 배분 로직위험 감소량·대응 시간·투입 비용의 다목적 비교상태·행동·보상 개념 설계 완료
관제 대시보드순찰 재배치와 정비 Top 5를 한 화면에서 판단UI·데이터 흐름 설계 완료

제안서와 대시보드 설계는 상태 데이터 → 의사결정 → 현장 조치 → 피드백을 하나의 흐름으로 연결합니다. 아래는 설계안이 실제로 유효한지 확인하기 위해 남은 질문입니다.

판단할 질문다음 검증에 필요한 근거
동적 배분이 더 나은가같은 교통·보행 시나리오에서 고정 순찰과 비교한 도달 시간, 위험 노출 시간, 안전 커버리지
위험 점수가 현실을 반영하는가TTC·PET, 조도, 제보의 실측 보정과 시간대별 오탐·누락 검토. 상황 가중치는 현재 제안값
현장에서 실행할 수 있는가순찰 인력·정비 예산 제약, PM 사업자 연동 가능성, 운영자 승인 기준, 개인정보 처리 및 장애 대응 검토
성과 수치의 범위

대시보드의 대응 시간이나 위험도 예시값은 화면 구성용입니다. 검증된 성과로 사용하지 않았으며, 사고 감소·비용 절감은 후속 실험에서 확인해야 할 목표입니다.

09A

회고

팀장으로서 배운 점

팀장 역할에서 가장 크게 배운 것은 기술 스택을 많이 제시하는 것보다 서로 다른 전공의 판단 기준을 하나의 의사결정 언어로 번역하는 일이 중요하다는 점입니다. 처음에는 모든 위험 신호와 기능을 넣으려 했지만, 실제 사용자가 지금 답해야 하는 질문을 기준으로 단기 순찰과 장기 정비를 분리하면서 팀의 논의가 빨라졌습니다.

다음 버전에서는 SUMO 비교 환경을 구축하고 실험을 실행해 예시값을 실제 수치로 교체하고, 안전 개선 효과뿐 아니라 개인정보·운영 비용·장애 시 기본 정책까지 함께 비교하겠습니다. “AI가 최적이라고 말했다”가 아니라, 팀이 합의한 기준과 데이터로 왜 그 배치를 선택했는지 설명할 수 있는 시스템을 만드는 것이 남은 목표입니다.

인하대학교 교내 경진대회 제출본을 포트폴리오 활용 목적으로 재구성한 자료입니다.
