지원 서류에 바로 쓰는 문장

복사해서 쓰되, 회사 직무에 맞춰 맨 앞 한 문장만 바꾸면 됩니다.

칫솔 제조 전 공정을 Arena로 모델링해 대기시간 데이터로 병목을 특정하고, 검수 통합·U자형 셀 배치·배치 출고 제거 세 가지를 설계해 시간당 생산량을 85.7% 끌어올린 프로젝트입니다.

이력서 항목

  • 사출–인쇄–식모–결합–포장 5개 공정과 검사·이동·포장 분기를 Arena로 모델링(8시간 × 5 replication), Waiting Time 리포트로 병목 대기열 상위 3개를 정량 특정
  • 공정마다 반복되던 직렬 검사 모듈을 병렬 통합 검수존으로 재설계하고, 직선형 라인을 U자형 셀로 재배치해 이동 시간 47.4% 단축
  • 출고 직전 50개 배치 공정을 1개 흐름으로 전환해 평균 리드타임 905.6 → 648.4분(−28.4%), 시간당 생산량 182 → 338ea(+85.7%) 달성

면접에서 나올 질문

왜 하필 이 세 가지를 골랐나요?
감이 아니라 대기시간 리포트에서 출발했다고 답하세요. 상위 병목이 결합·묶음·검사에 몰려 있었고, 각 병목의 원인 유형(배치 대기 / 흐름 단절 / 동선)에 하나씩 대응시킨 구조입니다.
세 개 중 어느 개선이 가장 효과가 컸나요?
지금 모델은 세 개를 동시에 적용한 결과만 있습니다. 단독 적용 실험을 안 했다는 점을 인정하고, “다시 한다면 각 안을 개별로 켜고 끄는 요인 실험을 설계하겠다”로 마무리하는 편이 훨씬 좋게 들립니다.
검사를 줄였는데 불량이 새어 나가지 않나요?
검사 항목 자체를 없앤 게 아니라 시점을 모아 병렬로 처리한 것이라고 설명하세요. 다만 불량률을 KPI로 측정하지 않은 건 한계이니 먼저 인정하는 편이 안전합니다.
replication 5회면 신뢰할 수 있나요?
일부 대기열은 half width가 평균만큼 커서(캡_핸들_결합 426.8 ± 371.8) 신뢰구간이 넓습니다. 이 지표는 반복 횟수를 늘려야 한다고 먼저 말하면 오히려 점수를 얻습니다.
U자형 배치를 Arena에서 어떻게 표현했나요?
Station 간 이동 시간 파라미터 조정과 Resource Set 공유로 구현했다는 점, 즉 물리 배치를 모델 파라미터로 번역한 과정을 설명하면 됩니다.

제출 전에 손볼 곳

원본 발표자료를 그대로 옮기면서 눈에 걸린 부분입니다. 면접관이 파고들기 쉬운 순서로 적었습니다.

  1. ‘평균 이동 시간’의 정의가 값과 맞지 않습니다 정의 칸에는 “실제 작업을 수행한 비율”이라고 적혀 있는데 값은 399.1 min입니다. 정의를 “제품 1개당 누적 이동 시간”으로 고치세요.
  2. 리드타임 905.6분이 런 길이 480분보다 깁니다 8시간 런에서 나온 평균 리드타임이 8시간을 넘는 이유(초기 과부하, warm-up 미설정, 미완료 엔티티 처리 방식)를 한 줄로 준비해 두세요. 가장 먼저 들어올 질문입니다.
  3. Warm-up이 0이고 replication이 5회입니다 정상상태 도달 전 구간이 통계에 섞입니다. 여유가 되면 warm-up을 주고 replication을 10~20회로 올려 다시 돌린 값으로 교체하면 수치 신뢰도가 확 올라갑니다.
  4. 품질·비용 지표가 없습니다 생산성만 좋아진 그림이라 “품질은?”이 반드시 따라옵니다. 불량률이나 재공품 수 같은 지표 하나만 추가해도 이야기가 완결됩니다.
  5. 본인 역할이 비어 있습니다 맨 위 메타 항목에 담당 파트(모델링 / 데이터 수집 / 개선안 설계 / 발표)를 구체적으로 채우세요. 5인 팀플에서 채용 담당자가 가장 궁금해하는 항목입니다.
