01 / Overview

무엇을, 왜 만들었나

제품의 정의와 포지셔닝

명함을 처음 갖게 되는 사람 — 대학생·취준생·1년차 — 에게는 명함이 수집 대상이 아니라 첫인상입니다. 리멤버가 잘하는 "명함을 스캔해 쌓아두는 일" 대신, 예쁜 첫 명함을 만들어 건네고 그 인연을 이어가는 일에 제품을 맞췄습니다.

리멤버·HiHello·Blinq·Popl 4종을 뜯어보고 나서 포지셔닝을 "예쁜 첫 명함 → AI 관계 비서"로 확정했습니다. 경쟁 앱이 교환의 순간에서 끝난다면, 잇츠미는 교환 이후 — 언제 어디서 만났는지, 얼마나 연락이 뜸해졌는지, 다시 만나기 전 무엇을 기억해야 하는지 — 를 다룹니다.

02 / Architecture

어떻게 굴러가나

클라이언트 · 서버 · 외부 API의 경계

API 키를 앱에 넣지 않는다는 원칙 하나로 구조가 정해졌습니다. AI 호출과 소셜 로그인 토큰 교환은 전부 Cloud Functions를 거칩니다.

클라이언트는 React Navigation 없이 Animated API 기반 커스텀 네비게이터를 직접 구현했습니다(useNativeDriver: true로 전환을 네이티브 스레드에서 처리). 화면 11개 · 서비스 모듈 27개 · 공용 컴포넌트 11개 구성.

스토어 심사

App Store 반려 3건을 원인별로 나눠 통과시키기

iOS build 14
증상
1.4 제출본이 2.1a(구글 로그인 크래시), 5.1.1(카메라 권한 목적 미고지), 2.1(미완성 NFC 기능 노출)로 연속 반려.
원인
세 건의 성격이 전부 달랐습니다. 크래시는 코드 결함, 권한은 Info.plist 문구 누락, NFC는 릴리즈 노트에만 있고 동작하지 않던 기능이었습니다.
해결
크래시는 로그인 플로우 수정, 권한은 사용 목적 문구를 화면 맥락에 맞게 재작성, NFC는 구현 대신 제거를 선택해 심사 리스크를 없앴습니다. 위치 권한 누락(ITMS-90683)도 함께 처리.
결과
재제출 후 통과. 이후 1.4.1 · 1.4.2 업데이트까지 반려 없이 배포.
플랫폼 대응

Android 16에서 키보드가 입력창을 가리는 문제

증상
안드로이드 이식 후 로그인·명함 편집 화면에서 키보드가 입력창을 덮어 무엇을 치는지 보이지 않음.
원인
targetSdk 36에서 엣지투엣지가 강제되면서 기존 adjustResize 동작이 무력화된 것. 표면적으로는 RN 문제처럼 보였지만 실제로는 OS 정책 변경이었습니다.
해결
임시로 targetSdk를 낮추는 우회 대신, MainActivity.kt에서 WindowInsetsCompat.Type.ime() 인셋을 콘텐츠 하단 패딩으로 직접 적용해 표준 동작을 복원했습니다.
결과
에뮬레이터 실검증 — 로그인·편집 양쪽 모두 키보드 위로 정상 상승. 최신 SDK를 유지한 채 해결.
데이터 동기화

"살아있는 명함"이 갱신되지 않던 끊긴 체인 찾기

증상
상대가 명함을 수정해도 내 지갑 속 명함이 그대로. 기능 자체가 조용히 동작하지 않는 상태.
원인
서로 다른 두 지점의 결함이 겹쳐 있었습니다. ① 내 명함에 ownerId가 없어 QR에 빈 값이 실림 ② 지갑 구독이 originalCardId만 조회하는 필드 불일치.
해결
발급-저장-구독으로 이어지는 ownerId 체인 전체를 복구하고, onSnapshot 전역 실시간 구독 + Cloud Functions 트리거(onMyCardUpdated) → FCM 푸시를 연결. 이직·승진을 구분해 알림 문구를 다르게 냈습니다.
결과
앱 내 실시간 갱신 + 백그라운드 푸시 E2E 검증 통과. 변경 이력이 AI 만남 브리핑에도 반영됨.
운영 비용

조회 분석이 Firestore 읽기를 선형으로 태우던 문제

증상
내 명함 조회 통계를 볼 때마다 조회 이력 전체를 읽어옴. 사용자가 늘수록 요금이 그대로 따라 오르는 구조.
원인
기능을 먼저 붙이느라 읽기 범위를 설계하지 않았습니다. 화면 진입 = 전체 컬렉션 스캔.
해결
전체 이력 읽기를 제거하고 필요한 집계·기간만 읽도록 재작성. 조회 기록도 불필요한 Cloud Run 왕복을 없애고 클라이언트에서 직접 기록하도록 정리.
결과
기능(주간 차트 · 최다 조회자 · 최근 목록)은 유지한 채 읽기량을 사용량과 분리.
안정성

가끔 로그인이 풀리던 경쟁 상태(race condition)

증상
분명 로그인해 뒀는데 앱을 켜면 가끔 로그인 화면으로 튕김. 재현이 들쭉날쭉했습니다.
원인
스플래시 2.5초 타이머가 Firebase의 세션 복원보다 먼저 끝나면, 클로저에 갇힌 user = null을 읽고 로그인 화면으로 보내던 것.
해결
인증 상태를 userRef로 분리해 타이머 만료 시점의 최신 값을 참조하도록 수정. 같은 패턴(stale closure)이 화면 전환에도 있어 screenRef로 함께 정리.
결과
자동 로그인 실패 재발 없음.
실사용자 피드백

내 기기에서는 안 나던 버그 — 어머니 휴대폰

증상
가족·지인에게 설치해 보게 했더니 명함 이미지 저장이 실패. 제 기기에서는 한 번도 나지 않던 문제였습니다.
원인
사진 권한을 이미 허용해 둔 개발 기기에서만 테스트한 탓. 권한 요청 자체가 없었고, 저장 실패 시 폴백도 없었습니다.
해결
사진 권한 요청 + 앨범 저장 폴백 추가. 같은 방식으로 모인 문제들(지갑 카드 1장일 때 정렬 틀어짐, 다크모드에서 카테고리 글자 안 보임, 편집 화면 키보드 답답함)을 8월 릴리즈에 묶어 반영했습니다.
결과
"내 기기에서 되는 것"과 "출시된 앱이 되는 것"이 다르다는 걸 기준으로 삼게 된 계기.
04 / AI

AI를 붙인 방식

기능이 아니라 구조로 다뤘습니다

모델 호출을 앱에서 직접 하지 않고 Cloud Functions 프록시(claudeProxy) 한 곳으로 모았습니다. 키가 앱 번들에 실리지 않고, 모델을 바꿔도 앱을 재배포할 필요가 없습니다.

기능모델 · 방식설계에서 신경 쓴 점
종이 명함 인식Claude Sonnet (Vision)문서 스캐너로 자동 크롭 → base64 전송 → 이름·직함·연락처 JSON 파싱. AbortController로 20초 타임아웃, 단계별 진행 문구 표시, 결과를 저장 전에 사용자가 수정할 수 있게 함
만남 브리핑Claude Haiku만남 맥락 + 대화 타임라인 + 명함 변경 이력을 묶어 "다시 만나기 전 30초 요약" 생성. 결과를 카드에 저장해 재진입 시 재호출하지 않음
안부문자 초안Claude Haiku어색한 첫 문장을 대신 씀. 원탭 SMS 또는 복사, 발송하면 타임라인에 기록
한줄 소개 생성Claude Haiku이름·직함·소속만으로 초안 → 다시 만들기 / 저장
운영프록시 레벨 처리모델이 폐기돼 AI 기능이 한 번에 죽은 적이 있어, 프록시에서 폐기 모델을 자동 치환하도록 바꿔 앱 업데이트 없이 복구
